# تیکت‌چی — سیستم تیکت پشتیبانی وردپرس

## نسخه ۲.۰ — هلپ‌دسک SaaS

| بخش | امکانات |
|---|---|
| **صندوق پشتیبانی** | نمای سه‌ستونه (نماها/دپارتمان‌ها/برچسب‌ها · فهرست · گفتگو)، «تیکت‌های من»، «بدون مسئول»، «در خطر SLA»، جستجوی سریع، عملیات گروهی، پیش‌نویس خودکار، میانبرهای صفحه‌کلید (`J/K`، `R`، `N`، `A`، `/`، `?`)، بروزرسانی زنده |
| **تیم و تخصیص** | نقش «کارشناس پشتیبانی»، سپردن تیکت به کارشناس، تخصیص خودکار نوبتی یا کم‌کارترین، دسترسی هر کارشناس محدود به دپارتمان‌های خودش |
| **SLA** | مهلت اولین پاسخ و حل بر اساس اولویت، ساعات کاری، تایمر در فهرست و تیکت، هشدار نقض مهلت |
| **یادداشت داخلی و تاریخچه** | یادداشت‌های تیم که مشتری نمی‌بیند، یادداشت ثابت تیکت، برچسب‌های رنگی، تاریخچه کامل تغییرات |
| **پروفایل ۳۶۰ مشتری** | اطلاعات تماس، آمار تیکت‌ها، رضایت، سفارش‌ها و مبلغ خرید ووکامرس، تیکت‌های قبلی |
| **اعلان‌ها** | زنگوله اعلان در پنل، ایمیل برندشده برای مشتری و کارشناس، پیامک (از جمله کاوه‌نگار) |
| **اتوماسیون** | سازنده بصری «وقتی ← اگر ← آنگاه» با الگوهای آماده؛ ۶ رویداد، ۸ شرط، ۷ کار (سپردن، اولویت، وضعیت، برچسب، یادداشت، پاسخ خودکار، اطلاع‌رسانی) |
| **گزارش‌ها** | ۸ شاخص با مقایسه دوره قبل، روند روزانه، عملکرد کارشناسان، رضایت، نقشه حرارتی ساعات پرترافیک، خروجی CSV |
| **پایگاه دانش** | مقاله‌های راهنما، مرکز راهنما با شورت‌کد `[ticketchi_kb]`، پیشنهاد مقاله هنگام نوشتن تیکت |
| **جستجوی سراسری** | `Ctrl/⌘ + K` در همه صفحات تیکت‌چی |

معماری و API: [ARCHITECTURE.md](ARCHITECTURE.md) · دیزاین سیستم: [DESIGN-SYSTEM.md](DESIGN-SYSTEM.md)

## نیازمندی‌ها

- PHP ۷.۴ به بالا · وردپرس ۵.۳ به بالا
- ووکامرس اختیاری است (بدون آن از شورت‌کد `[tickets]` استفاده کنید)
- `inc/admin/abstract/base-menu.php` و فایل لایسنس با ionCube رمزگذاری شده‌اند و به ionCube Loader نیاز دارند.

## ساختار

```
core.php                 بوت افزونه
src/                     هسته v2 (namespace Ticketchi\) — دامنه، SLA، تیم، اعلان، اتوماسیون، گزارش، REST
inc/                     لایه سازگاری v1 (تیکت، پاسخ، آپلود، پیامک، AJAX، هلپرهای UI)
inc/admin/               منو، دپارتمان‌ها، داشبورد، تنظیمات (Codestar)
views/front/             قالب‌های پنل کاربری
views/admin/             قالب‌های پنل مدیریت (partials/ = شل برنامه)
assets/shared/           توکن‌ها، کامپوننت‌ها، فونت
assets/front|admin/      CSS و JS هر پنل
tests/                   محیط تست و تست‌های end-to-end
```

## تست

تست‌ها یک وردپرس کامل (SQLite) + ووکامرس می‌سازند، داده نمونه وارد می‌کنند و همه جریان‌ها را در مرورگر واقعی (Playwright) اجرا می‌کنند:

```bash
WP_SRC=/path/to/WordPress \
SQLITE_SRC=/path/to/sqlite-database-integration \
WC_SRC=/path/to/woocommerce \
WP_CLI_PHAR=/path/to/wp-cli.phar \
tests/run-all.sh
```

| مجموعه | پوشش |
|---|---|
| `tests/e2e/front.test.cjs` | فیلترها، ثبت تیکت با پیوست، پاسخ، پیام صوتی، بستن تیکت، امتیاز، کنترل دسترسی، موبایل، شورت‌کد |
| `tests/e2e/admin.test.cjs` | داشبورد، حالت تاریک، صندوق پشتیبانی (جستجو، نماها، پاسخ، یادداشت داخلی، برچسب، مسئول، عملیات گروهی، Ctrl+K)، REST، اتوماسیون، گزارش‌ها و CSV، ارسال تیکت، دپارتمان‌ها و برچسب‌ها، محدوده دسترسی کارشناس، تنظیمات، امنیت، موبایل |
| `tests/e2e/edge.test.cjs` | حالت‌های خالی، تنظیمات مختلف، اعتبارسنجی سمت سرور، اجرا بدون ووکامرس |
| `tests/e2e/install.test.cjs` | نصب تازه، ارتقا از نسخه قبلی، فعال بودن هم‌زمان نسخه قدیم و جدید (آپلود از گیت‌هاب) |

## ارتقا از نسخه قبلی

ارتقا از ۱.x به ۲.۰ خودکار است: با اولین بارگذاری، ستون‌ها و جدول‌های جدید ساخته می‌شوند و هیچ داده‌ای حذف نمی‌شود. پیوندهای قدیمی (ایمیل‌ها و بوکمارک‌های «ویرایش تیکت») به صندوق جدید هدایت می‌شوند.

اگر افزونه را از فایل zip گیت‌هاب نصب می‌کنید، نام پوشه با نسخه قبلی (`ticketchi`) فرق دارد و وردپرس آن را افزونه‌ای جدا در نظر می‌گیرد:

1. نسخه قبلی تیکت‌چی را **غیرفعال و حذف** کنید (اطلاعات تیکت‌ها در پایگاه داده می‌ماند).
2. نسخه جدید را نصب و فعال کنید.

اگر هر دو هم‌زمان فعال باشند، نسخه جدید بدون خطا کنار می‌کشد و در پیشخوان پیام راهنما نمایش می‌دهد.

> `tests/stubs/base-menu.php` فقط در محیط تست جایگزین فایل رمزگذاری‌شده‌ی `BASE_MENU` می‌شود و در افزونه منتشر نمی‌شود.
